Test Search Fields in Your App

Use this test when the indexed field contains the visitor’s words and the profile leaves that field out of Search Fields.

  1. Choose a safe test profile. Confirm with your web team which App and profile live search uses. Use a Sandbox or staging App if available. Confirm no live site uses the App and profile you’ll test.
  2. Record the baseline in Preview. Select the test App, language, and profile. Try the visitor’s query, the distinctive title query, and an unrelated query. Record whether the target page appears and which results appear first.
  3. Go to Configurations, then Basic Configurations, then Search Fields. Select the indexed text field that contains the visitor’s words and save a draft. If the field is unavailable, reload the schema to refresh the field list. If it’s still missing, ask the indexing owner to verify that the field is populated.
  4. Publish to the confirmed test profile only and repeat the same searches in Preview. Check that the visitor’s query finds the correct URL and that the page is still findable by title. Compare the top results for the unrelated query and review unexpected changes with your team before publishing to live search.

Detailed Synonyms setup

In Optimizations → Synonyms, the visitor’s abbreviation goes in Word and the wording on the page goes in Synonym to. Use the one-way arrow to connect them.

  1. Choose where to test. Use a Sandbox or staging App that serves no live searches. Confirm the App and language with your team. The Search Profiles in that language share the App’s synonym dictionary.
  2. Record your baseline. In Preview, select that App, language, and the profile you want to check. Search for the visitor’s term, the term on the page, and an unrelated phrase. Note the result count, the first result, and where the target page appears. Confirm the target page is indexed and its wording is in a tokenized full-text Search Field.
  3. Open Optimizations, then Synonyms. In Word, enter the visitor’s term. Choose the one-way arrow in Is and enter the term the page uses in Synonym to. Add the pair and save a draft. If both terms should match content written with either term, consider the two-way option and test both directions.
  4. Review what will publish. Check that the Synonyms draft contains the intended change. If your account has Smart Match Assist, publishing Synonyms also applies any pending Smart Match Assist changes. Open Optimizations → Smart Match Assist and review Recommendations and Activity Log if available. Confirm with your team that the pending changes are ready before selecting Publish in Synonyms for the test App and language.
  5. Repeat the three searches in Preview. Confirm the visitor’s term now finds the target page, the page’s own term still finds it, and the unrelated search returns the same results in the same order. Repeat in other affected profiles your team uses. Share the comparison with your team before rolling out to live search.

Filter by content type

Try a broad search and look for a filter that narrows the list to what visitors came to find. The related Site Search setting is Faceting.

Ask your search owner

“Could visitors filter [example search] by [content type or category] so they can find [what they’re looking for]?”
Detailed Faceting setup
  1. Confirm where to test. Identify the App, language, and Search Profile the site uses. Use a test profile that serves no live searches. In Preview, run a broad query and record its result count and the kinds of pages it returns.
  2. Choose an indexed field. For categories like content type, use a String field so values stay intact. If the field or expected values are missing, ask the indexing owner to check how they’re populated.
  3. Open Configurations, then Basic Configurations, then Faceting. Select Enable Faceting, then choose a Facet Field and enter a Label visitors will understand. Set Max. Facet Values and Value Sorting. Add the facet, save a draft, and publish to the test profile only.
  4. Repeat the broad query in Preview. Check the facet label and values. Select a value and confirm the count drops and the remaining pages share that value. Clear it and confirm the original results return. If the facet works in Preview but is missing or behaves differently on your test site, ask your web team to verify the filter controls and the profile your site uses.

    Try This in Your Search App

    1. Choose a safe test App. Confirm with the web team which App, language, and profile your site uses. Use a Sandbox or staging App that serves no live searches. In Preview, use the test App, intended language, and profile.
    2. Record the baseline. Pick a typo from your no-results searches. Confirm the typo returns zero results and the correct spelling finds the intended page. Record the target URL and the top results for the correctly spelled search.

    Test Ranking in Your App

    1. Choose a safe test profile. Confirm the App, language, and profile used on the live site. Select a test profile that serves no live searches. Use a Sandbox or staging App if available.
    2. Record the baseline in Preview. Select the test App, language, and profile. Pick two common searches where you want useful matches higher and one search that already works well. Record the top five in relevance order and the positions of the pages you expect to move.
    3. Go to Configurations, then Advanced Configurations, then Ranking. Enable Field Ranking if needed. Under Search Field, add the field you want to boost. Try a small value, such as 1.5 for the title, if that field is already searchable and its matches are useful. If it’s empty or inconsistent, ask the indexing owner to check it first.
    4. Save a draft and publish to the confirmed test profile only. Rerun the same searches in Preview. Check that the intended pages move up for the first two searches and compare the top five for the search you want to keep stable. Review any unwanted changes before publishing to live search.

          Do This in My Search App

          Choose the page you want to put first and the words visitors use to find it. You can set up the promotion if you have permission to manage Promotions in your Search App.

          1. Confirm where you'll test. Ask your web team which Search App and Search Profile the live site uses, including which default profile it uses if none is specified. Use a Sandbox or staging App if available. Confirm that no live search uses the App and profile you plan to test. If you're unsure, ask your Search App admin before publishing.
          2. Record what you see now. In Preview for the test profile, run the trigger phrase, a longer search that includes it, and an unrelated search. For each, note what comes first and where your page appears, if at all.
          3. Go to Optimizations → Promotions and select Create a Promotion. Name the promotion and select Create.
          4. Enter a trigger phrase. Choose Contains to include longer searches with the full phrase, or Exact Match to match just the phrase.
          5. Under Indexed Items, select the page you want to feature. Select Save Draft.
          6. Publish to the test profile only. Check the selected profile before you publish. Open Preview, select that same profile, and repeat the three searches. Confirm the correct page is first in the regular results for the trigger phrase. For the longer search, it should be promoted only with Contains. For the unrelated search, the page should get no promotion and the first result should match what you recorded.
          7. Record the before-and-after results. If a check fails, review the trigger, match type, and selected page in the test profile. Once the checks pass, share your results and follow your team's process for publishing to live search.
